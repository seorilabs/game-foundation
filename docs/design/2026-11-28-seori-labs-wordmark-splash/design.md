# Seori Labs 조직 공통 시작 화면

v3 · 2026-11-28 · 검토 대기

## 화면과 시작 순서

가로와 세로 화면 모두, 공식 투명 원본 `seori-labs-logo-stacked-reverse.svg`의 심볼과 영문 `SEORI LABS` 워드마크를 사용한다. SVG는 공식 사이트 main `7e57199d5485f4748ad0da395f28ec596630a4b0`에 게시된 파일이며 SHA-256은 `b55486b2aa48ce6100602445712f063b1e71da5d72eeec202eeb25f124c5690c`이다. 로고 전체를 안전 영역 중앙에 둔다. 크기는 안전 너비의 56%, 개발 논리 좌표 320px, 안전 높이의 38% 안에서 종횡비를 유지해 맞춘다.

```text
단색 #020B16 OS 시작 → 투명 영문 로고를 올린 단색 화면 1초 → 각 게임의 기존 타이틀
                                           ↳ 타이틀 초기화는 동시에 진행
```

OS, Godot 초기 프레임, 로고 아래 배경의 색을 맞춘다. 그림과 한글 로고를 제거한다. Android 시작 drawable은 투명하고 iOS 시작 스토리보드는 이미지 참조가 없다. 이전 iOS 이미지 이름을 쓰는 앱에서는 새 시작 리소스와 연결을 검증한다. 출력 플랫폼의 초기화가 첫 게임 프레임을 낸 뒤 1초 정지한다. 일반 모드는 최대 150ms 페이드, 모션 감소는 즉시 전환이다. 표시 중 입력은 타이틀에 전달되지 않고, 복귀·언어 전환·초기화 재시도는 표시를 반복하지 않는다. 준비가 길거나 실패하면 기존 타이틀의 준비·오류·재시도 화면을 쓴다.

## 적용 경로

1. `seorilabs-official`은 Studio 페이지의 기본 시안과 내려받는 시작 화면을 투명 영문 원본 중심으로 갱신한다. 한영 페이지의 그래픽은 같은 영문 워드마크를 사용한다. 공식 사이트 병합 후 공개 주소의 HTML과 원본 해시를 읽는다.
2. `game-foundation`은 기존 `studio_splash`의 진입 구조에서 한 개의 공식 투명 로고와 공통 표시 동작을 제공한다. 로고용 파일, 제거 가능한 그림 파일, 각 소비자의 잠금 값을 함께 확인한다. `starter-template-game`은 검증한 foundation 커밋을 고정하고 새로 생성한 게임의 기본 시작 화면에서 사용한다.
3. 공유 `game-outgame-framework`의 에셋 위치와 검수 절차를 갱신한다. 공통 환경의 관련 링크와 참조를 검증한다.
4. [대상 저장소](scope.md)의 실제 게임 시작 경로에 같은 공통 스플래시를 적용한다. 이미 공통 묶음을 쓰는 게임은 고정 커밋으로 갱신하고, 독립 구조의 게임에는 공통 시작 모듈과 필요한 플랫폼 포장 연결만 적용한다. 각 게임의 고유 타이틀과 기존 초기화·저장 동작을 보존한다. 블룸핸드를 먼저 적용하고 기존 iPhone 증상 검증을 연결한다. Betta Raising의 열린 PR #23은 관련 변경과 CI 차단을 확인하고 중복 작업을 피한다.
5. 게임 작업의 끝 지점은 개발 검수와 저장소 PR 병합이다. 공식 사이트는 공개 읽기 확인까지 진행한다. 각 게임의 스토어 변경에는 따로 승인된 릴리스 계획이 필요하다.

## 인수조건과 테스트

| 조건 | 검증 |
| --- | --- |
| LOGO-1 공식 사이트와 공통 모듈, 생성 게임의 투명 영문 로고가 원본과 일치한다. | 게시 URL 해시, bundle 잠금, 새 템플릿 생성 검사. |
| LOGO-2 세로·가로·태블릿에서 심볼과 이름이 잘리지 않는다. | 320×568, 390×844, 568×320, 844×390, 768×1024 실제 Godot 렌더. 공통 화면을 서로 다른 검수자가 세 차례 실행하고 읽는다. 웹 페이지는 모바일·데스크톱과 라이트·다크에서 확인한다. |
| LOGO-3 첫 렌더부터 한 번만 약 1초간 보이고 타이틀에 도달한다. | 경과 시간, 모션 감소, 표시 중 탭·키 입력, 빠른·느린 준비, 준비 실패·재시도, 복귀를 실행한다. |
| LOGO-4 이전 그림과 한글·엔진 로고가 시작 과정에 안 나온다. | 게임별 실제 채택 플랫폼의 내보내기 테마, 리소스, 부팅 설정과 Web 로더를 검사한다. 블룸핸드 iPhone의 업데이트 확인은 기존 저장을 유지한 첫 실행·재실행이 대상이며, 후보 설치에 필요한 기기 범위는 개발 검수 후 따로 소명한다. |
| LOGO-5 기존 게임의 시작, 저장, 주요 흐름이 통과한다. | 각 저장소 승인 후보의 L3 개발 회귀와 CI를 확인한다. 제품별 상태를 기록하고 실제 게임 업데이트와 개발 원본 병합을 각각 표시한다. |

각 저장소의 검수 계획은 기존 기능 목록과 현재 기본 브랜치 또는 출시 기준을 사용한다. 해당 저장소에 변경 증거와 검증 결과를 남기며 공개 사이트와 게임의 출시 끝 지점은 위 범위를 따른다. 복구는 각 저장소 PR을 되돌리고, 공통 템플릿은 직전 bundle 잠금으로 복원한다.
